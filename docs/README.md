# Documentación del proyecto

Esta carpeta reúne el contexto de producto y las restricciones para evolucionar la demo. Los documentos describen el estado objetivo; no sustituyen las instrucciones obligatorias de [`../AGENTS.md`](../AGENTS.md).

## Orden de lectura recomendado

1. [`prospect-brief.md`](prospect-brief.md): problema, audiencia, propuesta comercial y alcance.
2. [`design-limits.md`](design-limits.md): límites visuales, de contenido y de uso de activos.
3. [`reuse-notes.md`](reuse-notes.md): partes reutilizables de la plantilla y riesgos conocidos.
4. [`implementation-plan.md`](implementation-plan.md): secuencia sugerida de patches pequeños.
5. [`readiness-checklist.md`](readiness-checklist.md): controles previos a una entrega o demostración.

## Criterio de mantenimiento

- Mantener aquí decisiones duraderas del proyecto, no instrucciones temporales de una máquina concreta.
- Actualizar el brief o el plan cuando cambie el alcance.
- Evitar duplicar reglas que ya estén definidas en `AGENTS.md`.
- No guardar capturas, exportaciones, paquetes comprimidos ni salidas generadas dentro de `docs/`.
